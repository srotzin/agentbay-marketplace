Clinical Trials Matching Tutorial (MCP)

Find trials, screen eligibility, match candidates, and keep coordinators in the loop.

When this tutorial helps
  • Patient navigation: find trials based on diagnosis, biomarkers, and geography.
  • Site recruitment: pre-screen candidates and prioritize outreach with explainable matches.
  • Sponsor ops: track enrollment status to forecast timelines and unblock bottlenecks.

1) Collect a patient profile

Start with a structured profile. Keep it minimal at first, then enrich as you learn more.

{
  "tool": "clinical_trials_patient_profile",
  "args": {
    "patientId": "p_001",
    "condition": "Non-small cell lung cancer",
    "age": 61,
    "sex": "F",
    "location": {
      "country": "US",
      "state": "CA",
      "city": "San Diego"
    },
    "biomarkers": ["EGFR exon 19 deletion"],
    "priorTherapies": ["osimertinib"],
    "notes": "Non-smoker, ECOG 1"
  }
}
Privacy note

Avoid sending direct identifiers. Use an internal patientId and redact free-text notes when possible.

2) Search for candidate trials

Search by condition, biomarkers, geography, sponsor, phase, and recruitment status.

{
  "tool": "clinical_trials_search",
  "args": {
    "query": "EGFR exon 19 deletion NSCLC",
    "phase": [2, 3],
    "recruiting": true,
    "near": {"city": "San Diego", "radiusMiles": 150},
    "limit": 25
  }
}
Tip

Run two searches: one strict (biomarker + recruiting + local) and one broad (condition-only + remote/telehealth allowed) to avoid missing options.

Common failure mode

Trial records can lag. Always validate contact details and recruitment status before outreach.

3) Match and explain eligibility

Pass trial candidates plus the patient profile to generate a ranked list with rationale and missing-data requests.

{
  "tool": "clinical_trials_match",
  "args": {
    "patientId": "p_001",
    "trialIds": ["NCT00000000", "NCT11111111"],
    "explain": true
  }
}

In production, store the explanation and the fields that drove the decision (e.g., biomarker match, age range, exclusion criteria) for auditability.

4) Create an outreach packet

Once a trial is promising, build a coordinator-friendly summary (without PHI unless your workflow is approved for it).

{
  "patientId": "p_001",
  "trialId": "NCT00000000",
  "summary": {
    "condition": "NSCLC",
    "keyBiomarkers": ["EGFR exon 19 del"],
    "age": 61,
    "priorTherapies": ["osimertinib"],
    "questions": [
      "Is prior osimertinib allowed?",
      "Are brain metastases permitted if stable?"
    ]
  }
}

Send the packet via your preferred communications tool (email / ticket / CRM note) and record the attempt.

5) Track match and enrollment status

Update status over time so the agent can nudge, follow up, and forecast.

{
  "tool": "clinical_trials_match_status",
  "args": {
    "patientId": "p_001",
    "trialId": "NCT00000000",
    "status": "screening",
    "lastContactedAt": "2026-04-08",
    "nextFollowUpAt": "2026-04-11",
    "notes": "Coordinator requested latest labs"
  }
}
