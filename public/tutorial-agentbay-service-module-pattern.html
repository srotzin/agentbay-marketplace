Building AgentBay Service Modules: Pattern + Checklist

This guide explains the service module conventions used by AgentBay’s MCP tool router and how to add new verticals quickly without breaking the dispatcher chain.

What is a “service module” in AgentBay?

A service module is a small, self-contained file in src/services/ that exports:

  • Tool definitions (name, description, JSON schema) so the MCP server can expose them.
  • A handler that performs the work when the tool is invoked.
  • Optional helpers (parsers, validators, API wrappers) that keep the handler readable.

AgentBay aggregates tools from many modules into a single registry and routes each tool call to the right handler via src/mcp-tools.js.

Service module file structure (recommended)

// src/services/my-vertical-service.js
export const tools = [
  {
    name: 'my_vertical_do_thing',
    description: '…',
    inputSchema: {
      type: 'object',
      properties: { /* … */ },
      required: [/* … */]
    }
  }
];

export async function handleTool(name, args, ctx) {
  switch (name) {
    case 'my_vertical_do_thing':
      return await doThing(args, ctx);
    default:
      return null;
  }
}

async function doThing(args, ctx) {
  // validate inputs
  // call APIs or internal services
  // return JSON-serializable result
}

Why this layout works: it keeps tool metadata near the handler and ensures the dispatcher can call handleTool consistently across services.

Naming conventions that avoid collisions

  • Tool names: use snake_case with a clear prefix, e.g. insurance_claims_…, clinical_trials_…, industrial_maintenance_….
  • One module, one prefix: keep a single prefix per file to simplify routing and future refactors.
  • Schema keys: prefer explicit names (patientAge, facilityId) over generic (id, value).

Input schema checklist (MCP-friendly)

When defining inputSchema:

  • Use type: 'object' at the top level.
  • List properties with stable types (string/number/boolean/array/object).
  • Set required for critical fields (avoid making everything optional).
  • Add description fields for user-facing clarity.
  • For arrays, define items and keep them uniform.

Tip: If a parameter can be large (e.g. freeform text), add length guidance in the description to reduce model failure modes.

Phase wiring: how tools get discovered

AgentBay organizes tool exports into “phase files” under src/mcp-tools-phases/. When you add a new module, it should be imported into a phase file and then included by src/mcp-tools.js.

  1. Create a service file in src/services/.
  2. Import it into a new or existing phase file in src/mcp-tools-phases/.
  3. Ensure the phase file exports a tools array (the aggregator imports these).
  4. Update src/mcp-tools.js to include the new phase in the overall tools registry.
  5. Add a dispatch entry so requests are routed to the new module’s handler.

If your tool definitions exist but dispatch is missing, the tool will show up in listings but fail at execution time.

Router integration: the “dispatch chain” checklist

Before committing, confirm:

  • The new module exports tools and handleTool.
  • The relevant phase file imports the module and spreads tools into its export.
  • src/mcp-tools.js imports the new phase file.
  • src/mcp-tools.js includes the phase’s tools in the aggregated toolsArray.
  • The dispatcher calls your module’s handleTool (and short-circuits when it returns a result).

Validation steps (always do these)

  1. Run node --check src/mcp-tools.js to catch syntax errors early.
  2. Start the server locally and invoke the tool with a minimal payload.
  3. Try one “edge input” (missing optional fields, empty arrays, longer text) to confirm validation behavior.

Common mistakes

  • Tool name mismatch: the dispatcher checks the exact string; keep names consistent.
  • Forgetting to export tools: a module without a tools export is effectively invisible.
  • Returning non-serializable values: Dates, streams, or class instances may break JSON encoding.
  • Mixing prefixes: it becomes difficult to search and to route later.
