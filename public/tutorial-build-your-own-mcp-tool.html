How to Build Your Own MCP Tool (HiveAgent Quickstart)

This guide shows the fastest, most reliable way to add a new tool to HiveAgent: create a service module, wire it into a phase file, register it in mcp-tools.js, and validate the build.

What you build

You will create a new service module in src/services/ that exports:

  • mcpToolSpecs: an array of JSON schema-like tool specs
  • handleToolCall(name, args): a dispatcher that returns a JSON response

Then you will expose the tool(s) by importing them into a phase file in src/ and registering them in src/mcp-tools.js.

Step 1 — Create a service module

Start from an existing module in src/services/ and follow the same conventions: naming, schema structure, and return types.

Example skeleton:

// src/services/my-vertical.js
export const mcpToolSpecs = [
  {
    name: "my_vertical_doThing",
    description: "Does a specific job for a vertical.",
    inputSchema: {
      type: "object",
      properties: {
        query: { type: "string", description: "User query" }
      },
      required: ["query"]
    }
  }
];

export async function handleToolCall(toolName, args) {
  if (toolName === "my_vertical_doThing") {
    return {
      content: [
        { type: "text", text: JSON.stringify({ ok: true }, null, 2) }
      ]
    };
  }
  return null;
}

Keep the tool output stable: return plain JSON, avoid HTML in tool responses, and include ok/error fields for easier agent consumption.

Step 2 — Add tools to a phase file

HiveAgent groups tools into phase files (for organization and incremental growth). Create a new phase file when you add a new vertical or when an existing phase is already crowded.

Example pattern:

// src/mcp-tools-phaseNN-my-vertical.js
import { mcpToolSpecs as myVerticalToolSpecs } from "./services/my-vertical.js";

export const phaseNNToolSpecs = [
  ...myVerticalToolSpecs
];

Step 3 — Register tools + dispatch

In src/mcp-tools.js you typically:

  • Import the new phase specs and append them to the master toolsArray
  • Import your service handleToolCall and add it to the dispatch chain so tool execution resolves

Keep the dispatch chain ordered and make sure your handler returns null when it does not recognize the tool name.

Step 4 — Validate locally

At minimum, run a syntax check for the tool registry:

node --check src/mcp-tools.js

If the project has additional scripts (lint/test), run them too.

Quality checklist

  • Naming: tool names are unique and prefixed by vertical
  • Schema: inputSchema uses correct JSON types and required fields
  • Determinism: responses are JSON with consistent keys
  • Safety: no secrets, no filesystem access without explicit parameters
  • Wiring: tools appear in tools/list and tool calls route to your handler
